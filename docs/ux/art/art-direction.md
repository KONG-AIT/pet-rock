# Art Direction

## 문서 목적

이 문서는 애완돌 키우기의 공식 Art Direction을 정의해요.

아트 에셋 제작자, UI/UX 작업자와 구현 작업자는 이 문서를 공통 기준으로 사용합니다.

다음 항목을 결정하는 것을 목표로 해요.

* 게임 오브젝트와 배경이 어떤 인상을 가져야 하는지
* 화면마다 돌, 식물, 화분과 UI를 어떻게 구분해서 표현하는지
* 날씨와 시간 변화를 어떤 레이어 구조로 확장하는지
* 정적 에셋과 motion의 책임을 어떻게 나누는지
* 초기 Vertical Slice에서 무엇을 만들고 검증하는지

방향 검토용 참고 자료는 다음 두 가지예요.

* [아트 가이드 이미지](./art-guide.png): 전체 분위기, 종이 콜라주 표현, 색상과 레이어 확장 예시
* [돌 비교 시안](./rocks/rock-design-guide.png): `rock-01~03`의 모티프, 실루엣과 표면 특징 비교

두 이미지는 최종 runtime asset이나 화면별 제작 계약이 아니에요. 이미지 속 식물, 표정, 크기와 배치는 방향을 검토하기 위한 예시이며, 이미지와 본문이 다르면 본문을 기준으로 합니다. 제품 방향과 충돌하면 [Product Identity](../../product/identity.md)와 [Product Principles](../../product/principles.md)를 우선해요.

화면의 역할과 상태는 [Screens](../screens.md), 레이아웃과 시각적 우선순위는 [Wireframes](../wireframes/wireframes.md), 화면 간 이동은 [Flows](../flows.md)를 기준으로 해요. 이 문서는 그 구조 위에 적용할 Visual Design과 motion의 방향을 정의합니다.

# 1. Art Direction

전체 비주얼은 **종이 콜라주 느낌을 기반으로 한 따뜻하고 단순한 스타일**을 사용해요.

잘 다듬어진 캐릭터 상품처럼 매끈하게 보이기보다, 작은 종이 조각을 손으로 오려 붙여 만든 세계처럼 느껴져야 합니다. 다만 질감과 불규칙성을 많이 더하는 것 자체가 목적은 아니에요.

사용자가 화면을 봤을 때 가장 먼저

> 작고 소중한 내 돌이 조용히 놓여 있다.

라는 느낌을 받을 수 있어야 해요.

## 핵심 키워드

* 담백함
* 따뜻함
* 자연스러움
* 단순함
* 작고 소중한 느낌
* 약간의 손맛
* 충분한 여백

## 기본 표현 원칙

### 1. 형태가 질감보다 먼저 보여야 해요

돌과 식물에는 약한 종이 질감과 손그림 느낌을 사용할 수 있어요.

하지만 작은 모바일 화면에서도 오브젝트의 실루엣과 상태를 바로 구분할 수 있어야 합니다. 질감, 선, 장식이 형태를 흐리게 만들지 않아요.

### 2. 완벽한 대칭보다 자연스러운 불규칙성을 사용해요

실루엣은 단순하게 유지하되 약간 비대칭으로 표현해요. 가장자리, 잎의 각도와 종이 면에서 작은 차이를 둘 수 있습니다.

지나치게 매끈한 벡터 형태, 정확히 반복되는 패턴과 강한 3D 표현은 사용하지 않아요.

### 3. 빛과 입체감은 절제해요

강한 그림자, 광택과 극적인 명암은 사용하지 않아요.

바닥과 오브젝트의 관계를 보여줄 필요가 있다면 약하고 부드러운 접지 표현만 사용합니다. 그림자가 캐릭터의 일부처럼 강하게 보이거나 별도 에셋 재사용을 방해하지 않아야 해요.

### 4. 여백도 장면의 일부예요

빈 공간을 장식으로 채우지 않아요. 충분한 여백은 돌을 바라보는 경험과 작은 변화를 발견하는 데 사용합니다.

특히 홈에서는 배경 장식이나 UI가 돌과 현재 장착한 식물보다 먼저 눈에 들어오지 않아야 해요.

# 2. 게임 오브젝트

## 돌

돌은 일반적인 캐릭터보다 **돌다운 존재**로 보여야 해요.

돌은 generic gray rock을 반복해서 색만 바꾸지 않고, 실제 돌의 종류를 모티프로 사용해요. 모티프는 실루엣, 기본 색감과 표면 특징을 정하는 출발점이며, 지질 표본처럼 사실적으로 재현하기 위한 규칙은 아닙니다.

기본 rock 방향은 다음과 같아요.

| ID | 모티프 | 주요 구분 요소 |
| --- | --- | --- |
| `rock-01` | 강자갈 | 물에 닳은 듯 둥글고 안정적인 실루엣, 따뜻한 회색 또는 베이지 계열, 절제된 작은 점무늬 |
| `rock-02` | 화강암 | 강자갈보다 각과 면이 느껴지는 불규칙한 실루엣, 밝은 warm gray 계열, 작은 광물 점을 단순화한 무늬 |
| `rock-03` | 현무암 | 단단하고 묵직한 실루엣, dark gray 계열, 제한된 작은 기공 또는 점 형태의 표면 특징 |

각 모티프의 특징은 종이 콜라주와 단순화된 손그림 질감으로 번역해요. 실사 사진 질감, 실제 돌 표면을 그대로 붙인 texture와 과도하게 세밀한 광물 표현은 사용하지 않습니다.

* 돌은 항상 바닥에 놓여 있어요.
* 홈에서는 화분이나 받침대 위에 올리지 않아요.
* 돌마다 실루엣, 색감, 종이 질감과 점무늬에서 차이를 둬요.
* 단순하고 약간 비대칭인 형태를 사용해요.
* 작은 점 형태의 눈은 사용할 수 있어요.
* 얼굴은 돌을 구분하는 핵심 특징으로 사용하지 않고 최소한으로 표현해요.
* 복잡한 표정 변화로 감정을 직접 설명하지 않아요.
* 감정과 반응은 얼굴보다 작은 움직임을 중심으로 표현해요.

같은 돌이 화면에 따라 다른 캐릭터처럼 보이지 않아야 합니다. 돌 선택, 홈과 식물 보관함에서 크기와 배치는 달라질 수 있지만 형태와 고유한 특징은 유지해요.

`rock-01~03` 비교 시안은 실제 에셋 제작에서 세 돌의 차이와 family resemblance를 판단하는 visual reference로 사용해요. 비교 시안은 화면별 runtime asset이 아니며, 최종 에셋과 충돌할 경우 이 문서의 모티프와 표현 원칙을 우선합니다.

## 식물

식물은 알아보기 쉬운 형태를 사용하되 지나치게 사실적으로 묘사하지 않아요.

* 식물마다 전체 실루엣에서 차이가 보여야 해요.
* 잎 하나하나가 작은 종이 조각처럼 느껴질 수 있어요.
* 돌과 어울리는 저채도 자연색을 기본으로 사용해요.
* 돌 머리에 장착했을 때 작은 화면에서도 종류를 구분할 수 있어야 해요.
* 완전히 성장한 식물은 돌 머리에 자연스럽게 장착할 수 있어야 해요.

식물에는 성장 상태를 표현할 비주얼 에셋이 필요합니다. 단계 수, 각 단계의 구체적인 모양과 성장 상태를 공통 에셋으로 표현할지 식물별 에셋으로 표현할지는 기능 설계에 따라 결정해요.

성장은 단계별 비주얼이 바뀌는 것으로 표현하되, 특정 식물의 잎이 정해진 순서로 나타나는 것처럼 하나의 성장 연출을 모든 식물의 규칙으로 고정하지 않아요.

## 화분과 정원

화분은 `S03 내 정원`에서 씨앗과 식물의 성장 상태를 보여주는 오브젝트예요.

* 씨앗 심기 전, 성장 중과 성장 완료 상태를 구분할 수 있어야 해요.
* 식물은 완전히 성장하기 전까지 정원의 화분에서 자라요.
* 성장 상태 확인과 정원 관련 행동은 정원에서 관리해요.
* 화분도 종이 콜라주 세계에 어울리는 단순한 형태와 절제된 질감을 사용해요.

화분은 홈에 두지 않아요. 홈의 장식 요소로도 사용하지 않습니다.

# 3. 홈 배경

홈은 **내 돌을 보는 화면**이에요.

배경은 실제 방이나 장소를 사실적으로 재현하기보다, 종이 콜라주로 만든 작은 무대처럼 표현해요. 아이보리 또는 베이지 계열의 바탕과 찢어진 색종이 면을 제한적으로 사용할 수 있습니다.

홈 장면의 시각적 우선순위는 다음과 같아요.

```text
돌 + 현재 장착한 식물
→ 작은 환경 변화
→ 최소한의 배경 장식
→ UI
```

* 돌이 항상 장면의 시각적 중심이어야 해요.
* 현재 장착한 식물은 돌 머리 위에 표현해요.
* 돌 위쪽에는 식물 실루엣을 위한 충분한 공간을 남겨요.
* 배경 장식은 최소화해요.
* 돌보다 먼저 눈에 들어오는 큰 소품, 강한 패턴과 높은 대비는 사용하지 않아요.
* 홈에는 화분을 배치하지 않아요.

# 4. 날씨와 시간 확장

날씨와 시간은 하나의 완성된 배경을 상태마다 새로 만드는 방식보다, 공통 장면에 필요한 레이어를 더하는 방식으로 확장해요.

기본 합성 구조는 다음과 같습니다.

```text
기본 배경
+ 날씨 / 시간 레이어
+ 돌 / 현재 장착한 식물
+ 필요한 전경 효과
+ UI
```

각 레이어는 다른 환경 상태와 조합할 수 있어야 하고, 돌과 식물의 canonical asset을 교체하지 않아야 해요.

## 표현 예시

| 상태 | 사용할 수 있는 표현 |
| --- | --- |
| 맑음 | 해 모양 종이, 따뜻한 색감 |
| 흐림 | 회색 구름, 전체 채도 감소 |
| 비 | 구름, 제한된 빗방울 |
| 눈 | 작은 흰 종이 조각 |
| 바람 | 작은 잎 조각, 식물의 약한 흔들림 |
| 낮 | 밝은 기본 배경과 자연스러운 따뜻한 색감 |
| 노을 | 절제된 노란색 또는 주황색 시간 레이어 |
| 밤 | 달, 별, 어두운 배경 레이어 |

날씨와 시간을 조합하더라도 다음 기준을 유지해요.

* 새로운 상태가 추가될 때마다 전체 배경을 복제하지 않아요.
* 환경 효과가 돌의 실루엣과 현재 장착한 식물을 가리지 않아요.
* 비, 눈과 작은 파티클은 화면을 계속 바쁘게 만들지 않아요.
* 시간 레이어가 UI의 대비와 가독성을 해치지 않아요.
* 어떤 상태에서도 돌이 화면의 중심으로 남아 있어야 해요.

# 5. Color

기본적으로 저채도 자연색을 사용해요.

## 기본 색상 계열

* Ivory
* Beige
* Warm Gray
* Dark Gray
* Sage Green
* Olive Green
* Brown

## 포인트 색상 계열

필요한 경우 다음 색상을 제한적으로 사용할 수 있어요.

* Blue
* Yellow
* Orange
* Muted Red

포인트 색상은 상태나 작은 강조를 명확하게 만드는 데 사용합니다. 한 화면에 강한 포인트 색상을 많이 배치하거나, 색의 강도만으로 시각적 관심을 만들지 않아요.

정확한 색상값과 상태별 palette는 실제 에셋과 UI theme을 제작할 때 별도로 확정합니다. 어떤 색을 선택하더라도 UI 텍스트와 아이콘의 가독성은 질감이나 분위기보다 우선해요.

# 6. UI

게임 오브젝트와 UI는 서로 다른 표현 책임을 가져요.

| 구분 | 표현 방식 |
| --- | --- |
| 게임 오브젝트 | 종이 콜라주, 약한 손그림 질감, 자연스러운 불규칙성 |
| UI | 깔끔함, 단순함, 충분한 여백, 명확한 아이콘, 높은 가독성 |

UI까지 손그림이나 종이 질감으로 만들 필요는 없어요. 장식적인 질감보다 화면 상태와 행동을 빠르게 이해할 수 있는 구성을 우선합니다.

UI는 배경과 어울려야 하지만 게임 오브젝트처럼 보이면 안 돼요. 사용자가 터치할 수 있는 요소와 장면의 일부를 명확하게 구분할 수 있어야 합니다.

# 7. Motion

Motion은 화려한 연출보다 작은 물리적 반응을 중심으로 해요.

기본적으로 다음 움직임을 재사용합니다.

| 움직임 | 기본 표현 |
| --- | --- |
| 눌림 | `scale` + `translate` |
| 기울기 | 작은 `rotate` |
| 붙음 | 이동 + 약한 overshoot |
| 등장 | `opacity` / `scale` / 작은 이동 |
| 후행 | 가벼운 오브젝트가 본체보다 조금 늦게 따라오는 움직임 |

직접적인 interaction은 대체로 `150~350ms` 범위의 짧은 반응을 사용해요. 이 범위는 일관된 출발점이며, 오브젝트의 크기와 상태 전달에 따라 조정할 수 있습니다.

지속적으로 반복되는 큰 idle animation은 최소화해요. 움직임은 사용자의 행동에 반응하거나 사용자가 작은 변화를 발견하도록 돕는 정도로 사용합니다.

`prefers-reduced-motion: reduce`에서는 핵심 상태를 motion 없이도 이해할 수 있어야 해요. animation을 제거해도 에셋, 배치와 상태 표현이 유지되어야 합니다.

# 8. 주요 Interaction

## 돌 터치

돌이 살짝 눌리거나 작은 각도로 기울어진 뒤 원래 상태로 돌아와요. 현재 장착한 식물처럼 가벼운 오브젝트는 돌보다 조금 늦게 따라올 수 있습니다.

반응은 돌이 살아 있는 캐릭터처럼 크게 움직이는 것이 아니라

> 방금 얘가 조금 움직였나?

정도의 작은 존재감을 만드는 데 사용해요.

## 연속 터치

필요한 경우 작은 보조 반응을 더할 수 있어요. 단, 보조 반응이 반복 입력을 강하게 유도하거나 화면의 중심을 파티클로 채우지 않아야 합니다.

## 씨앗 심기

씨앗이 화분에 들어가 성장 상태가 시작되었음을 짧게 표현해요. 장면 전체를 바꾸기보다 씨앗과 화분의 관계가 이해되는 작은 이동과 상태 전환을 우선합니다.

## 성장

시간에 따라 준비된 단계별 비주얼 에셋으로 전환해요. motion이 없어도 현재 성장 상태의 차이를 구분할 수 있어야 합니다.

식물의 정체는 [Screens](../screens.md)의 공개 규칙에 따라 완전히 성장했을 때 처음 보여줘요. 중간 단계가 최종 식물의 정체를 지나치게 직접적으로 드러내지 않아야 합니다.

## 성장 완료

완료 상태를 인지할 수 있는 짧은 강조를 사용해요. 완성된 식물의 형태가 연출보다 먼저 보여야 합니다.

## 머리에 장착

식물이 돌 머리 위로 이동해 약한 overshoot와 함께 자연스럽게 정착하는 느낌을 사용할 수 있어요. 장착 후에는 돌과 식물이 하나의 안정된 실루엣으로 보여야 합니다.

## 보관

완성된 식물이 보관 상태로 전환되었음을 짧고 명확하게 표현해요. 특정 용기나 포장 형태를 모든 식물의 canonical asset에 포함하지 않고, 보관함 UI의 상태 표현과 분리합니다.

---

# 9. 에셋 제작 원칙

## Canonical asset을 재사용해요

같은 돌과 식물을 화면별로 따로 제작하지 않아요.

예를 들어 `rock-01`은 돌 선택, 홈과 보관함 Preview에서 같은 canonical asset을 사용합니다. `rock-01-home`, `rock-01-storage`처럼 화면 이름을 붙인 복제 에셋을 만들지 않아요.

화면별 차이는 가능한 한 다음 요소로 구성합니다.

* 크기와 위치
* 레이어 순서
* 코드 기반 `transform`과 `opacity`
* 별도 그림자 또는 접지 레이어
* 날씨와 시간 레이어
* 작은 파티클
* UI 선택 상태와 touch 반응

## 정적 에셋과 motion의 책임을 분리해요

애니메이션을 위해 프레임 이미지를 대량 제작하는 방식을 기본으로 사용하지 않아요.

정적 에셋에 `transform`과 `opacity` 기반 motion을 적용하는 방식을 우선합니다. 상태 자체의 형태가 달라질 때는 성장 단계처럼 필요한 정적 에셋을 별도로 만들어요.

## 조합을 전제로 제작해요

돌, 완성 식물, 배경과 환경 효과를 서로 분리해 재조합할 수 있어야 해요.

특히 다음 요소를 하나의 이미지에 미리 합치지 않아요.

* 돌과 현재 장착한 식물
* 돌과 날씨 효과
* 기본 배경과 특정 날씨 또는 시간
* 오브젝트와 UI 선택 상태
* 반복 사용되는 파티클과 특정 화면

에셋 포맷, 기준 해상도, 투명 여백, anchor와 파일 naming의 세부 계약은 실제 제작 전에 별도로 결정합니다.

---

# 10. 초기 Vertical Slice

전체 에셋을 한 번에 제작하지 않고, 하나의 작은 조합으로 Art Direction과 구현 가능성을 먼저 검증해요.

## 제작 범위

* `rock-01`
* `growth-planted`
* `growth-growing`
* `plant-01-final`
* `seed-basic`
* `pot-basic`
* `home-background`
* `weather-rain-layer`

`rock-02`, `rock-03`은 종류 모티프와 비교 시안의 기준만 함께 확인하고, 최종 runtime asset 제작은 이번 Vertical Slice에 포함하지 않아요.

## Interaction 범위

* 돌 터치
* 씨앗 심기
* 성장 상태 전환
* 성장 완료
* 식물 장착
* 비 오는 홈

이 범위는 전체 식물과 환경 에셋을 확장하기 전에 스타일, 레이어 분리와 작은 화면에서의 가독성을 확인하기 위한 검증 단위예요.

---

# 11. 검증 기준

초기 Vertical Slice와 이후 에셋은 다음 기준으로 검토해요.

## Art Direction

* 종이 콜라주 느낌이 보이지만 질감이 형태보다 먼저 보이지 않나요?
* 저채도 자연색, 단순한 실루엣과 약한 불규칙성이 일관되나요?
* 강한 그림자, 광택이나 과도한 3D 표현 없이 따뜻한 인상을 유지하나요?
* 작은 화면에서도 돌, 식물과 각 성장 상태를 구분할 수 있나요?
* `rock-01`이 generic gray rock이 아니라 단순화된 강자갈 모티프로 인식되나요?
* `rock-01~03` 비교 시안에서 얼굴이 아니라 실루엣, 색감과 표면 특징으로 서로 구분되나요?

## 제품과 화면 역할

* 홈에서 돌이 가장 먼저 보이나요?
* 돌이 바닥에 놓여 있고 홈에 화분이 없나요?
* 돌의 감정을 복잡한 표정보다 작은 움직임으로 표현하나요?
* 정원에서 씨앗 심기, 성장 중과 성장 완료 상태를 구분할 수 있나요?
* 성장 완료 전에는 최종 식물의 정체를 미리 드러내지 않나요?

## 확장성과 재사용

* 같은 돌과 식물의 canonical asset을 여러 화면에서 재사용할 수 있나요?
* 기본 배경과 비 레이어를 분리해 다른 날씨와 시간으로 확장할 수 있나요?
* 돌, 장착 식물, 날씨 효과와 UI가 독립적인 레이어로 조합되나요?
* 프레임 이미지 없이 정적 에셋과 기본 transform으로 주요 interaction을 표현할 수 있나요?

## UI와 Motion

* UI가 게임 오브젝트와 구분되고 텍스트와 아이콘을 쉽게 읽을 수 있나요?
* interaction이 짧고 절제되어 상태 변화와 결과를 이해하는 데 도움이 되나요?
* 반복되는 motion이 돌을 조용히 바라보는 경험을 방해하지 않나요?
* reduced motion에서도 같은 상태와 결과를 이해할 수 있나요?

## Vertical Slice 완료 기준

다음 흐름을 하나의 canonical asset 구성으로 확인할 수 있으면 초기 검증 범위를 충족해요.

```text
정원의 씨앗
→ 화분에 심기
→ 성장 단계 전환
→ 성장 완료와 식물 공개
→ 돌 머리에 장착
→ 기본 홈과 비 오는 홈에서 같은 돌 / 식물 조합 확인
→ 돌 터치 반응 확인
```

완료 여부는 에셋 개수보다, 이 흐름에서 Art Direction과 재사용 원칙이 함께 유지되는지를 기준으로 판단합니다.

---

# 12. 아직 결정하지 않은 것

이 문서는 방향과 제작 원칙을 확정하지만 다음 세부 사항은 아직 고정하지 않아요.

* `planted`, `growing` 상태의 구체적인 형태
* 성장 단계 에셋을 공통으로 사용할지 식물별로 만들지 여부
* 식물별 성장 전환 motion
* 정확한 palette 값과 상태별 색상 token
* 날씨와 시간 사이의 전환 방식

에셋 파일 형식, canvas, anchor, runtime directory와 Vertical Slice layer 계약은 [Vertical Slice Asset Specification](./asset-specification.md)을 기준으로 해요. 아직 결정하지 않은 항목은 실제 에셋 제작과 Vertical Slice 검증 결과에 따라 확정합니다.
