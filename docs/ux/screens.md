# Screens

## 0. 문서 목적

애완돌 키우기에 필요한 화면과 각 화면의 역할, 주요 요소, 핵심 행동을 정의해요.

이 문서는 화면 상태와 UI 행동 계약의 기준입니다. 화면 간 이동은 `flows.md`, 레이아웃과 시각적 우선순위는 `wireframes.md`를 기준으로 해요.

화면은 Product Identity와 Core Loop를 기준으로 설계해요.

### Product Identity

애완돌을 하나 데려와 식물을 키우고 꾸미며, 별것 아닌 변화를 즐기고 친구에게 자랑하는 가벼운 디지털 펫 게임이에요.

사용자가 느껴야 하는 가장 중요한 감정은 다음과 같아요.

> 내 돌이라서 괜히 귀엽다.

따라서 화면에서도 기능이나 정보보다 **돌 자체와 돌의 변화**가 가장 먼저 보여야 해요.

### Core Loop

```text
접속
 ↓
내 돌 확인
 ↓
시간 경과에 따른 변화 확인
 ↓
씨앗 심기
 ↓
식물 성장 기다리기
 ↓
완성된 식물 확인
 ↓
식물 장착 / 꾸미기
 ↓
변화한 돌 감상
 ↓
공유
 ↓
시간 경과
 ↓
다시 접속
```

식물은 씨앗을 심는 순간 내부적으로 종류가 결정돼요.

다만 사용자는 어떤 식물이 자라고 있는지 알 수 없으며, **완전히 성장했을 때 처음 식물의 정체를 확인해요.**

---

# 1. 화면 구성

주요 화면은 다음과 같아요.

| ID  | 화면     | 역할                        |
| --- | ------ | ------------------------- |
| S01 | 돌 선택   | 처음 함께할 돌을 선택하고 이름을 지어요.   |
| S02 | 홈      | 내 돌을 보고 상호작용하는 중심 화면이에요.  |
| S03 | 씨앗 심기  | 씨앗을 화분에 심고 성장 과정을 확인해요.   |
| S04 | 식물 보관함 | 완성된 식물과 보유 씨앗을 확인하고 관리해요. |

다음 기능은 별도 화면으로 만들지 않고 기존 화면의 상태 또는 Overlay로 처리해요.

* 이름 입력
* 복귀 변화 안내
* 복귀 보상
* 식물 성장 완료 상태: S03 내부 상태
* 식물 장착 결과
* 공유

---

# 2. S01. 돌 선택

## 역할

사용자가 처음 함께할 돌을 선택하고 이름을 지어요.

이 화면에서 가장 중요한 것은 캐릭터를 고르는 행동 자체보다

> 얘가 내 돌이다.

라는 느낌을 만드는 것이에요.

이름은 처음 돌을 데려갈 때만 정할 수 있어요.

돌을 데려간 이후에는 이름을 변경할 수 없어요.

---

## 주요 요소

### 1. 돌 후보

고정된 3종의 돌을 보여줘요.

각 돌은 외형이 달라요.

돌마다 능력치나 성능 차이를 보여주는 정보는 없어요.

사용자는 순수하게 외형과 느낌으로 돌을 선택해요.

---

### 2. 돌 선택

사용자가 원하는 돌을 터치해요.

돌을 선택하면 현재 화면 위에 **화면 대부분을 덮는 Overlay**가 열려요.

선택된 돌은 Overlay 안에서 크게 보여줘요.

기존 목록은 뒤쪽에 남아 있지만 어둡게 처리하여 선택한 돌에 집중할 수 있게 해요.

```text
돌 목록
 ↓
돌 터치
 ↓
[선택 Overlay]
선택한 돌을 크게 표시
```

시스템 Back 또는 X를 누르면 Overlay를 닫고 선택을 취소해요. 바깥 영역을 눌러서는 닫히지 않아요.

---

### 3. 이름 입력 Overlay

돌을 선택하면 열린 Overlay 안에서 이름을 입력해요.

별도의 이름 입력 화면으로 이동하지 않아요.

Overlay의 목적은

```text
이 돌을 골랐다
 ↓
이 돌에게 이름을 붙인다
```

라는 두 행동을 하나의 자연스러운 경험으로 연결하는 것이에요.

#### 입력 조건

* 이름 입력 필수
* 최소 1자, 최대 10자
* 한글 / 영문 / 숫자 입력 허용
* 앞뒤 공백 제거
* 공백만 입력할 수 없음
* 기본적인 부적절 입력 검증
* 이름 확정 후 변경 불가

자동 생성 이름은 기본값으로 제공하지 않아요.

사용자가 직접 이름을 정하는 행동 자체가 돌에 대한 첫 애착 형성의 일부예요.

이름은 `데려가기`를 누르는 순간 확정돼요.

---

### 4. 이름 변경 불가 안내

이름 입력 영역 주변에 이름을 이후 변경할 수 없다는 사실을 짧게 안내해요.

예:

```text
이름은 나중에 변경할 수 없어요.
```

경고처럼 강하게 표현하기보다, 확정 전에 알아야 하는 정보로 자연스럽게 보여줘요.

---

### 5. 데려가기

이름 입력이 완료되면 활성화돼요.

```text
돌 선택
 ↓
Overlay 표시
 ↓
이름 입력 완료
 ↓
데려가기 활성화
```

선택을 확정하면 돌 정보와 이름을 저장하고 홈으로 이동해요.

이름은 이 시점에 함께 확정돼요.

---

## 핵심 행동

```text
돌 살펴보기
→ 돌 선택
→ 선택한 돌 크게 확인
→ 이름 입력
→ 데려가기
```

---

## 화면 상태

### 초기 상태

```text
돌 목록 노출
Overlay 없음
```

### 돌 선택 상태

```text
돌 선택됨
선택 Overlay 열림
선택한 돌 크게 표시
이름 입력 가능
데려가기 비활성
```

### 입력 완료 상태

```text
선택 Overlay 열림
돌 선택됨
이름 입력됨
데려가기 활성
```

---

## 다음 화면

```text
[S01 돌 선택]
 ↓
돌 선택
 ↓
[이름 입력 Overlay]
 ↓
이름 입력
 ↓
데려가기
 ↓
이름 확정
 ↓
[S02 홈]
```

# 3. S02. 홈

## 역할

게임의 중심 화면이에요.

사용자는 앱을 실행했을 때 가장 먼저 자신의 돌을 확인해요.

홈의 가장 중요한 콘텐츠는 UI가 아니라 **내 돌**이에요.

사용자가 홈에 들어왔을 때 가장 먼저 드는 생각은

> 얘 지금 뭐 하고 있지?

여야 해요.

---

## 화면 우선순위

화면 안의 시각적 우선순위는 다음과 같아요.

```text
1. 돌
2. 돌 머리 위 식물과 시간에 따른 변화
3. 돌의 반응
4. 이름
5. 필요한 행동
```

버튼이나 메뉴가 돌보다 더 강하게 보여서는 안 돼요.

홈에는 행복도, 수분, 햇빛처럼 지속적으로 관리해야 할 것처럼 보이는 상태 게이지를 두지 않아요.

사용자가 숫자를 관리하는 게임보다 **돌을 바라보고 변화에 반응하는 경험**에 집중할 수 있어야 해요.

---

## 주요 요소

### 1. 돌

화면의 가장 큰 영역을 차지해요.

현재 상태의 돌을 보여줘요.

돌은 화면 중앙보다 조금 아래쪽에 위치할 수 있어요.

돌 위쪽에는 식물이 충분히 성장할 수 있도록 넉넉한 공간을 확보해요.

---

### 2. 머리 위 식물

현재 장착한 식물은 돌 머리 위에서 자라요.

별도의 화분이나 주변 장식으로 배치하지 않아요.

식물은 돌의 머리카락처럼 돌과 하나의 캐릭터 실루엣을 만들어요.

식물의 크기가 커지더라도 화면이 답답해지지 않도록 돌 위쪽의 성장 공간을 충분히 확보해요.

---

### 3. 시간에 따른 변화

시간 경과에 따른 변화는 돌과 주변 영역에서 보여줘요.

예:

* 머리 위 식물의 변화
* 이끼 발생
* 작은 환경 변화
* 돌의 반응 변화

변화는 가능하면 텍스트나 수치보다 시각적으로 먼저 보여줘요.

---

### 4. 돌 이름

사용자가 처음 돌을 데려갈 때 정한 이름을 보여줘요.

이름은 돌과 연결된 정보로 느껴질 수 있도록 상단 또는 돌 주변에 자연스럽게 배치해요.

예:

```text
몽돌
```

이름을 과도하게 UI 제목처럼 강조하지 않아요.

이름은 표시만 가능하며, 터치해도 변경 화면이나 입력 Overlay가 열리지 않아요.

---

### 5. 돌 터치

별도의 `쓰다듬기` 버튼은 제공하지 않아요.

사용자는 돌 자체를 터치해 상호작용해요.

```text
돌 터치
 ↓
쓰다듬기 반응
```

터치하면 짧은 반응을 보여줘요.

예:

* 움찔
* 살짝 흔들림
* 작게 통통 튐
* 표정 또는 눈 변화
* 짧은 반응 문구
* 작은 효과음

돌 자체가 상호작용 대상이라는 것을 자연스럽게 학습할 수 있어야 해요.

터치는 보상을 얻기 위한 반복 행동이 아니라 가벼운 교감이에요.

---

### 6. 돌의 반응

돌 아래쪽에 짧은 반응이나 상태 문구를 보여줄 수 있어요.

예:

```text
오늘도 와줘서 고마워!
```

```text
왠지 기분이 좋아 보여요.
```

정량적인 상태 대신 돌의 표정과 짧은 문장으로 상태를 전달해요.

---

### 7. 액션 메뉴

홈 하단에 큰 기능 버튼들을 나열하지 않아요.

우측 하단에 하나의 원형 액션 버튼을 배치해요.

기본 상태에서는 하나의 버튼만 보여요.

```text
●
```

버튼을 터치하면 필요한 행동들이 위쪽으로 펼쳐져요.

예:

```text
씨앗 심기
식물 보관함
공유
```

메뉴는 향후 기능이 추가되어도 같은 방식으로 확장할 수 있어요.

다만 항목을 과도하게 늘려 일반적인 앱 메뉴처럼 만들지는 않아요.

확장 메뉴는 시스템 Back, 액션 버튼 재터치, 바깥 영역 터치로 닫혀요. 메뉴 항목을 선택하면 메뉴가 닫힌 뒤 대상 화면으로 이동해요.

---

### 8. 씨앗 심기

액션 메뉴에서 선택할 수 있어요.

선택하면 `S03 씨앗 심기`로 이동해요.

식물을 직접 즉시 획득하는 행동이 아니라, **새로운 식물을 키우기 시작하는 행동**이에요.

---

### 9. 식물 보관함

액션 메뉴에서 선택할 수 있어요.

선택하면 `S04 식물 보관함`으로 이동해요.

완전히 성장한 식물을 확인하고 현재 돌 머리에 심을 식물을 변경할 수 있어요.

보유한 씨앗도 같은 화면에서 확인할 수 있어요.

---

### 10. 공유

현재 꾸며진 돌을 공유할 수 있어요.

별도의 공유 화면은 만들지 않아요.

현재 돌의 모습을 기반으로 공유용 이미지를 생성하고 OS Share Sheet로 연결해요.

---

# 4. 홈의 시간 변화

홈은 사용자가 앱을 떠난 동안 시간이 흘렀다는 사실을 보여주는 공간이기도 해요.

---

## 짧은 시간 후 재접속

특별한 변화가 없다면 별도의 안내 없이 현재 돌을 바로 보여줘요.

---

## 변화가 발생한 경우

홈에 들어왔을 때 달라진 모습을 먼저 보여줘요.

예:

```text
앱 실행
 ↓
변화한 돌 표시
 ↓
사용자가 변화 확인
 ↓
필요한 경우 짧은 안내
```

텍스트로 먼저 설명하기보다 **달라진 모습을 먼저 발견하게 하는 것**이 중요해요.

---

## 장기간 접속하지 않은 경우

돌에 시간의 흔적이 생길 수 있어요.

예:

* 이끼가 생김
* 주변에 작은 변화가 생김

현재 화분에서 성장 중인 식물이 있다면 그 식물 역시 시간이 흐르는 동안 성장할 수 있어요.

이는 페널티가 아니라 재미있는 변화예요.

사용자에게 죄책감을 주는 표현은 사용하지 않아요.

예:

```text
X 돌이 외로워했어요.
X 너무 오래 방치했어요.
X 연속 출석이 끊겼어요.

O 몽돌에게 이끼가 생겼어요.
O 없는 동안 조금 달라졌네요.
O 심어둔 씨앗이 조금 자랐어요.
```

---

# 5. 복귀 보상

복귀 보상은 홈 진입 과정에서 처리해요.

별도의 보상 화면으로 이동하지 않아요.

예:

```text
홈 진입
 ↓
돌 변화 확인
 ↓
복귀 보상 Overlay
 ↓
받기
 ↓
Overlay 닫힘
 ↓
홈
```

보상 안내가 돌을 완전히 가려버리지 않는 구조를 우선해요.

---

# 6. S03. 씨앗 심기

## 역할

보유한 씨앗을 화분에 심고 식물이 자라는 과정을 확인하는 화면이에요.

이 화면에서 중요한 감정은

> 뭐가 자랄까?

라는 작은 기대감이에요.

식물을 즉시 획득하는 화면이 아니에요.

사용자가 씨앗을 심고 기다린 뒤, 완전히 성장했을 때 어떤 식물인지 확인하는 경험을 만들어요.

---

## 기본 규칙

씨앗을 심는 순간 내부적으로 자라날 식물의 종류가 결정돼요.

하지만 이 정보는 사용자에게 공개하지 않아요.

```text
씨앗 심기
 ↓
내부적으로 식물 결정
 ↓
사용자에게는 비공개
 ↓
시간 경과
 ↓
성장 완료
 ↓
식물 공개
```

사용자는 성장 중인 식물의 형태만 보고 어떤 식물인지 확정적으로 알 수 없어야 해요.

---

## 주요 요소

### 1. 보유 씨앗

현재 보유한 기본 씨앗의 수량을 보여줘요.

예:

```text
기본 씨앗 ×N
```

현재 씨앗 종류는 `기본 씨앗` 하나예요.

같은 종류의 씨앗은 개별 아이템으로 취급하지 않고 수량으로 관리해요.

---

### 2. 화분

씨앗과 식물이 성장하는 중심 오브젝트예요.

씨앗을 심기 전에는 비어 있는 화분을 보여줘요.

씨앗을 심으면 화분 안에서 식물이 성장하기 시작해요.

화분은 돌 머리에 식물을 장착하기 전의 **임시 성장 공간**이에요.

---

### 3. 씨앗 심기

보유한 기본 씨앗을 하나 사용해 화분에 심어요.

```text
기본 씨앗 ×N
 ↓
씨앗 심기
 ↓
기본 씨앗 ×N
```

씨앗을 심는 순간 내부적으로 최종 식물 종류가 결정되지만 사용자에게는 보여주지 않아요.

---

### 4. 성장 상태

씨앗을 심은 뒤에는 화분에서 성장하는 모습을 보여줘요.

성장 단계는 구체적인 숫자나 게이지보다 시각적인 변화로 표현하는 것을 우선해요. 단계는 다음 3가지예요.

```text
심은 후 0시간 이상 ~ 3시간 미만: 심음
3시간 이상 ~ 6시간 미만: 자라는 중
6시간 이상: 다 자람
```

이 단계는 수치 게이지가 아니라 화분과 식물의 시각적 상태를 표현하기 위해 사용해요.

성장 중에는 돌 머리에 심을 수 없어요.

---

### 5. 성장 중 식물

성장 중에는 최종 식물의 종류를 공개하지 않아요.

사용자에게는

```text
조금씩 자라고 있어요.
```

```text
어떤 식물이 될까요?
```

정도의 정보만 제공해요.

종류, 이름, 희귀도 등 결과를 추측할 수 있는 확정 정보는 보여주지 않아요.

---

### 6. 성장 완료

식물이 완전히 성장하면 처음으로 식물의 정체를 공개해요.

예:

```text
다 자랐어요!

민들레
```

새로운 식물이라면 간단하게 신규 획득임을 알려줄 수 있어요.

과한 보상 연출이나 희귀도 강조는 필요하지 않아요.

---

### 7. 머리에 심기

완전히 성장한 식물만 돌 머리에 심을 수 있어요.

```text
성장 완료
 ↓
식물 공개
 ↓
머리에 심기
 ↓
[S02 홈]
```

장착하면 홈으로 이동하고, 돌 머리 위에 새 식물이 적용된 모습을 바로 보여줘요.

---

### 8. 보관하기

완성된 식물을 바로 머리에 심지 않고 보관할 수도 있어요.

보관한 식물은 `S04 식물 보관함`에서 다시 확인할 수 있어요.

---

## 핵심 행동

### 씨앗을 처음 심을 때

```text
씨앗 확인
→ 화분에 씨앗 심기
→ 성장 시작
```

### 성장 중

```text
S03 진입
→ 화분 확인
→ 성장한 모습 확인
→ 아직 완성되지 않았다면 돌아가기
```

### 성장 완료

```text
S03 진입
→ 성장 완료 확인
→ 식물 공개
→ 머리에 심기 또는 보관
```

---

# 7. 식물 성장 완료 상태

식물 성장 완료는 별도의 화면이나 Overlay로 만들지 않아요.

S03의 화면 상태로 처리해요.

---

## 주요 요소

### 완성된 식물

화분에서 다 자란 식물을 가장 크게 보여줘요.

이 시점부터 식물 이름을 공개해요.

---

### 신규 여부

처음 획득한 식물이라면 간단하게 표시할 수 있어요.

예:

```text
NEW
```

---

### 머리에 심기

완성된 식물을 먼저 보유 식물에 추가하고 현재 돌 머리에 적용해요.

적용 후 홈으로 이동하여 변화한 모습을 바로 확인해요.

---

### 보관하기

이미 보유 식물에 추가된 식물을 보관 상태로 두고 현재 머리 위 식물은 변경하지 않아요.

---

## Flow

```text
식물 성장 완료
 ↓
식물 공개
 ↓
[완료 상태]
 ├─ 머리에 심기 → 홈
 └─ 보관하기 → S04 식물 보관함
```

---

# 8. S04. 식물 보관함

## 역할

완전히 성장한 식물과 현재 보유한 씨앗을 확인하고 관리해요.

보관함은 `식물`과 `씨앗`을 탭으로 구분해요.

```text
[식물] [씨앗]
```

식물은

> 내 돌에 이걸 달면 어떻게 보이지?

를 확인하는 대상이고,

씨앗은

> 다음에 무엇을 키울 수 있지?

를 확인하는 자원이에요.

---

## 8.1 식물 탭

### 1. 식물 목록

완전히 성장하여 정체가 공개된 식물만 보여줘요.

성장 중인 식물은 이 목록에 포함하지 않아요.

식물은 Grid 형태로 보여줘요.

예:

```text
┌────┐ ┌────┐ ┌────┐
│ 🌱 │ │ 🌷 │ │ 🌵 │
└────┘ └────┘ └────┘
```

---

### 2. 미획득 식물

아직 획득하지 않은 식물을 실루엣 또는 잠금 상태로 보여줄 수 있어요.

미획득 식물도 목록에 노출하면 자연스럽게

> 이런 것도 있네.

라는 수집 동기를 만들 수 있어요.

다만 어떤 씨앗에서 어떤 식물이 나올지 직접적으로 연결되는 정보는 제공하지 않아요.

---

### 3. 식물 선택

식물을 선택하면 선택 상태를 표시해요.

선택한 식물이 돌 머리에 적용되었을 때의 모습을 Preview로 보여줄 수 있어요.

---

### 4. 장착

선택한 식물을 현재 돌 머리에 적용해요.

장착을 위해 별도의 확인 화면으로 이동하지 않아요.

```text
식물 선택
→ Preview
→ 머리에 심기
```

---

### 5. 현재 장착 식물

현재 사용 중인 식물은 목록에서 구분할 수 있어야 해요.

예:

* 체크 표시
* `장착 중`
* 선택 테두리

---

### 6. 식물 미장착

식물을 제거하고 아무 식물도 없는 기본 돌 상태로 돌아갈 수 있어요.

식물 목록에 `없음` 항목을 제공하는 방식이 가장 단순해요.

---

## 8.2 씨앗 탭

현재 보유한 씨앗을 확인해요.

씨앗은 개별 인스턴스를 카드 여러 개로 나열하지 않아요.

동일한 종류의 씨앗은 하나의 논리적 항목이며, 수량으로 관리해요.

현재 씨앗 종류는 하나예요.

```text
기본 씨앗
×N
```

씨앗 이미지는 돌이나 식물 캐릭터가 아니라 **씨앗 자체의 형태**로 보여줘요.

---

### 씨앗 심기

기본 씨앗 항목에서 `심기`를 선택하면 `S03 씨앗 심기`로 이동해요.

```text
[S04 씨앗 탭]
 ↓
기본 씨앗
 ↓
심기
 ↓
[S03 씨앗 심기]
```

---

## 8.3 빈 보관함

식물 탭에서는 완성된 식물이 하나도 없을 때 빈 상태를 보여줘요.

씨앗 탭에서는 보유한 씨앗이 하나도 없을 때 빈 상태를 보여줘요.

빈 상태에서는 작은 돌 캐릭터를 사용할 수 있어요.

예:

```text
아직 보관함이 비어 있어요.

씨앗을 심고 식물을 키워보세요!
```

필요하다면 `씨앗 심으러 가기` 행동을 제공할 수 있어요.

---

# 9. 공유

공유를 선택하면 현재 돌의 상태를 기반으로 공유 이미지를 만들어요.

공유용 이미지에는 최소한 다음 정보가 포함될 수 있어요.

```text
돌
현재 머리 위 식물
돌 이름
게임을 알 수 있는 작은 브랜딩
```

게임 UI 전체를 캡처하기보다는 돌 자체가 중심이 되는 공유용 이미지를 만드는 방향이 좋아요.

Flow:

```text
홈
 ↓
공유
 ↓
공유 이미지 생성
 ↓
OS Share Sheet
```

---

# 10. 화면으로 분리하지 않는 기능

다음 기능은 독립 화면을 만들지 않아요.

### 이름 입력

돌을 선택했을 때 S01 위에 열리는 Overlay에서 처리해요.

선택한 돌을 크게 보여주고 그 자리에서 이름을 입력해요.

이름은 `데려가기`를 누를 때 확정돼요.

### 이름 변경

이름 변경 기능은 제공하지 않아요.

홈에서 돌 이름을 터치해도 입력창이나 Overlay가 열리지 않아요.

### 쓰다듬기

별도의 버튼이나 화면을 제공하지 않아요.

홈에서 돌 자체를 터치하면 반응해요.

### 복귀 보상

홈의 Overlay로 처리해요.

### 식물 성장 완료

S03의 화면 상태로 처리해요.

### 식물 상세

보관함에서 식물을 선택했을 때 필요한 정보를 보여줘요.

### 꾸미기

식물 보관함의 Preview와 머리에 심기 기능으로 처리해요.

### 도감

식물 보관함에서 획득 / 미획득 상태를 함께 보여줘요.

### 공유

OS Share Sheet를 사용해요.

# 11. Navigation

홈을 중심으로 화면이 연결돼요.

```text
                       ┌────────────────┐
                       │   S01 돌 선택  │
                       └───────┬────────┘
                               │
                               ▼
                       ┌────────────────┐
                       │     S02 홈     │
                       └───────┬────────┘
                          ┌────┴────┐
                          │         │
                          ▼         ▼
                  ┌────────────┐ ┌──────────────┐
                  │S03 씨앗 심기│ │S04 식물 보관함│
                  └──────┬─────┘ └──────┬───────┘
                         │              │
             성장 완료 후 │              │ 식물 장착
              머리에 심기 │              │
                         └──────┬───────┘
                                ▼
                              S02 홈
```

S04의 씨앗 탭에서는 S03으로 이동할 수도 있어요.

```text
S04 씨앗 탭
 ↓
기본 씨앗 선택
 ↓
S03 씨앗 심기
```

Bottom Navigation은 사용하지 않아요.

홈이 다른 화면과 동등한 메뉴 중 하나가 아니라 게임 경험의 중심이기 때문이에요.

`씨앗 심기`, `식물 보관함`은 홈의 우측 하단 액션 메뉴에서 필요한 순간에 들어갔다가 다시 돌아오는 보조 공간이에요.

# 12. 화면별 핵심 질문

Wireframe을 만들 때 각 화면은 아래 질문에 답할 수 있어야 해요.

## S01 돌 선택

> 내가 어떤 돌을 데려갈지 쉽게 고를 수 있는가?

> 돌을 고른 뒤 선택한 돌 자체에 충분히 집중할 수 있는가?

> 선택한 돌에게 바로 이름을 붙일 수 있는가?

> 이름이 데려가기 이후 변경되지 않는다는 점이 자연스러운가?

## S02 홈

> 화면을 열자마자 내 돌이 가장 먼저 보이는가?

> 식물이 커져도 돌과 식물을 함께 충분히 보여줄 수 있는가?

> 돌 자체를 터치하고 싶게 보이는가?

> 이전과 달라진 점을 자연스럽게 발견할 수 있는가?

> 필요한 행동은 쉽게 찾을 수 있지만 돌보다 강하게 보이지 않는가?

## S03 씨앗 심기

> 씨앗을 화분에 심는 행동이 직관적인가?

> 어떤 식물이 자랄지 모르는 기대감이 유지되는가?

> 성장 중에는 결과가 너무 일찍 노출되지 않는가?

> 다 자랐을 때 식물이 공개되는 순간이 충분히 즐거운가?

## S04 식물 보관함

> 어떤 완성 식물을 가지고 있는지 쉽게 볼 수 있는가?

> 현재 머리에 심을 식물을 쉽게 바꿀 수 있는가?

> 식물과 씨앗이 명확하게 구분되는가?

> 같은 종류의 씨앗이 수량으로 자연스럽게 관리되는가?

---

# 13. 최종 화면 목록

```text
S01. 돌 선택
S02. 홈
S03. 씨앗 심기
S04. 식물 보관함
```

핵심 방향은 화면 수를 늘리는 것이 아니라,

```text
내 돌을 보고
→ 씨앗을 심고 기다리고
→ 자란 식물로 돌을 바꾸고
→ 다시 내 돌을 보는 것
```

을 자연스럽게 반복하게 만드는 것이에요.
