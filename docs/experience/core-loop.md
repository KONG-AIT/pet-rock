# Core Loop

## 이 게임에서 반복되는 경험은 무엇인가요?

이 게임의 핵심 반복 경험은 다음과 같아요.

> **돌을 보러 옴
> → 작은 변화나 보상을 발견함
> → 식물을 얻거나 돌과 상호작용함
> → 내 돌을 조금 더 꾸밈
> → 애착이 쌓임
> → 나중에 다시 돌을 보러 옴**

일반적인 방치게임처럼 생산량을 높이기 위해 반복하는 구조보다는,

> **다시 들어왔을 때 내 돌에게 무슨 일이 있었는지 궁금해지는 것**

을 재방문의 가장 중요한 이유로 생각합니다.

## 1. 돌을 보러 와요

사용자는 가끔 자신의 돌이 생각나서 게임에 들어와요.

매번 해야 할 일이 많아서 들어오는 것이 아니라,

> "얘 지금 뭐 하고 있지?"

정도의 가벼운 궁금증이면 충분합니다.

자주 방문하는 사용자는 조금 더 많은 변화와 상호작용을 볼 수 있지만, 오랫동안 방문하지 않았다고 손해를 보지는 않아요.

## 2. 무언가 달라진 것을 발견해요

게임에 들어왔을 때 이전과 완전히 똑같은 화면만 계속 보여준다면 다시 돌아올 이유가 줄어들어요.

따라서 시간이 지나면서 작은 변화가 생길 수 있습니다.

예를 들면,

* 식물이 조금 자라요.
* 새로운 상태가 나타납니다.
* 주변에 작은 변화가 생겨요.
* 돌이나 식물에서 평소와 다른 작은 움직임을 볼 수 있습니다.
* 새로운 식물을 얻을 수 있는 기회가 생겨요.

모든 방문마다 큰 이벤트가 발생할 필요는 없습니다.

중요한 것은

> **내가 없는 동안에도 시간이 조금 흘렀다는 느낌**

을 주는 것이에요.

## 3. 작은 행동을 해요

발견한 것을 확인한 다음에는 짧은 행동을 할 수 있어요.

예를 들면,

* 돌을 한번 만져봅니다.
* 식물에 물을 줘요.
* 얻은 보상을 확인합니다.
* 새로운 식물을 얻어봐요.
* 가지고 있는 식물을 바꿔봅니다.

한 번 접속했을 때 여러 행동을 반드시 수행해야 하는 구조는 지양해요.

원하는 것 하나만 하고 나가도 충분해야 합니다.

## 4. 내 돌을 조금씩 만들어요

식물을 얻고 꾸미면서 돌의 모습이 조금씩 달라져요.

이 과정에서 사용자가

> "이 조합이 얘한테 더 잘 어울리네."

같은 생각을 할 수 있었으면 합니다.

수집한 아이템의 숫자가 늘어나는 것보다, 내가 선택한 결과가 실제 돌의 모습에 반영되는 것이 더 중요해요.

시간이 지나면서 이름, 함께한 시간, 식물과 작은 변화들이 쌓이고,

> **다른 사람의 돌이 아니라 내 돌**

이라는 느낌이 만들어집니다.

## 5. 애착이 쌓여요

이 Loop의 최종 보상은 높은 수치가 아니에요.

사용자가 돌을 볼 때 조금 더 익숙하고 귀엽게 느끼는 것이 가장 중요한 결과입니다.

한 번의 강한 보상보다 작은 경험이 여러 번 쌓이면서 애착을 만드는 방향을 생각해요.

따라서 모든 시스템은 가능하면

> **이 행동이 내 돌에 대한 애착을 조금이라도 더 만들어주나요?**

라는 기준으로 검토합니다.

## 6. 다시 생각나서 돌아와요

게임을 종료하고 시간이 지나면 다시 작은 변화가 생길 수 있어요.

사용자는 그 변화를 확인하거나, 새 식물을 얻거나, 그냥 자신의 돌을 한번 보기 위해 다시 돌아옵니다.

그리고 다시 같은 Loop가 이어져요.

> 방문
> → 발견
> → 작은 행동
> → 꾸미기
> → 애착
> → 시간 경과
> → 다시 방문

## Supporting Loop

식물 수집은 Core Loop를 지원하는 중요한 반복 구조가 될 수 있어요.

예를 들면,

> 씨앗 보유
> → 씨앗 심기
> → 성장 완료
> → 식물 공개
> → 내 돌에 적용
> → 새로운 모습 확인

같은 흐름입니다.

다만 식물을 많이 모으는 것 자체가 게임의 목적이 되지는 않도록 합니다.

식물 수집은 항상 **내 돌을 더 다양하게 표현하고 애착을 강화하기 위한 수단**으로 사용해요.

## 아직 정하지 않은 것

Core Loop의 방향은 정의하지만, 다음 내용은 아직 확정하지 않습니다.

* 시간에 따라 정확히 어떤 변화가 생기는지
* 씨앗을 어떤 방식으로 얻는지
* 씨앗의 초기 지급량
* 하루에 몇 번 정도 의미 있는 행동을 할 수 있는지

이 부분은 이후 기능을 설계하면서 Core Loop와 Product Principles에 맞는 방법을 선택합니다.
