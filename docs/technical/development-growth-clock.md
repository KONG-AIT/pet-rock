# 개발용 식물 성장 시간 제어

## 목적

production의 6시간 성장 규칙과 저장 데이터는 그대로 유지하면서 개발 및 수동 테스트에서 S03 성장 경계를 빠르게 재현한다.

이 제어는 Vite development build에서만 로드된다. production build에는 제어 UI, query parameter, global hook을 제공하지 않는다.

## 사용 방법

1. `pet-rock` 디렉터리에서 `npm run dev`를 실행한다.
2. 돌을 선택하고 S03에서 씨앗을 심는다.
3. 화면 오른쪽 위의 `DEV 시간 제어` 표시를 연다.
4. 아래 시점 중 하나를 선택한다.
   - `+0시간 · 심은 직후`: 심은 시각과 동일
   - `+3시간 직전`: 3시간 경계 1ms 전
   - `+3시간 직후`: 3시간 경계 1ms 후
   - `+6시간 직전`: 완료 경계 1ms 전
   - `+6시간 직후`: 완료 경계 1ms 후
5. 선택 즉시 현재 화면의 성장 상태가 갱신된다. S02에서도 같은 성장 상태를 확인할 수 있다.
6. `+6시간 직후`에는 기존의 `머리에 심기` 또는 `보관하기`를 사용해 실제 수집·저장·장착 경로를 검증한다.

## offset 유지 정책

- 제어는 `plantedAt`을 수정하지 않고 개발 clock의 offset만 변경한다.
- 화면에는 누적 시스템 offset 대신 현재 성장의 `plantedAt` 기준 경과 시간을 표시한다. 새 식물을 심으면 다시 `+0시간`부터 표시된다.
- offset은 `localStorage`의 개발 전용 key에 저장되어 새로고침과 앱 재실행 후에도 유지된다.
- 실제 시간은 offset이 적용된 상태에서도 계속 흐른다.
- background에서 foreground로 돌아오면 App Store의 기존 `refreshGrowth()`를 호출해 화면과 저장 상태를 동기화한다.
- 잘못된 값, 음수 경과 시간, 30일을 넘는 비정상 offset은 무시한다.
- 완료된 성장을 과거 시점으로 이동해도 완료 상태를 되돌리거나 수집을 중복 수행하지 않는다.

## 자동화 검증

`npm test`는 다음 계약을 검증한다.

- 심은 직후, 3시간 전후, 6시간 전후의 clock 시각
- offset의 재실행 복원
- 손상된 값과 잘못된 과거 시점의 거부
- 기존 Store 테스트를 통한 성장 완료 1회 저장 및 수집·장착·보관 Flow

`npm run build` 후 산출물에 `DEV 시간 제어`와 개발 clock storage key가 없는지 확인한다.

## 제한 사항

- 성장 중인 식물이 있을 때만 경계 이동 버튼을 사용할 수 있다.
- seed 수량, 성장 결과 식물, `plantedAt`, production 성장 상수, game storage schema는 변경하지 않는다.
- 범용 시간 여행이나 사용자용 시간 가속 기능으로 사용하지 않는다.
